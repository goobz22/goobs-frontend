# List — a11y audit (2026-07-11)

**Status:** FIXED

**Component parts:** `List` (`<ul>`), `ListItem` (`<li>`), `ListItemIcon` (`<div>` wrapper),
`ListItemText` (`<div>` with `primary`/`secondary` `<span>`s).

## APG pattern

This is a **content structure ("list")**, not an interactive APG widget — there is no
composite keyboard model to implement (no roving tabindex, no arrow-key navigation, no
selection). The component renders native semantic `<ul>`/`<li>` and carries no interactive
handlers of its own; any interactivity (links/buttons inside a row) is supplied by the
consumer and lives in those child components. The relevant success criterion is therefore
**WCAG 1.3.1 Info & Relationships** (the list must be programmatically exposed AS a list).

## Issues found

### 1. `list-style: none` strips list semantics — no `role="list"` on the `<ul>` — FIXED
- **Severity:** moderate — **WCAG 1.3.1 Info & Relationships (Level A)**
- **Where:** `src/components/List/index.tsx:88` (the `<ul>`), caused by
  `src/components/List/List.module.css:14` (`list-style: none` on `.container`).
- **Problem:** WebKit/Safari + VoiceOver deliberately **remove the implicit `list` role from a
  bulletless `<ul>`** (and, with it, the `listitem` role from its `<li>` children). With
  `list-style: none` and no explicit `role`, VoiceOver no longer announces "list, N items" and
  drops list-navigation, so the grouping relationship between the rows is lost for those users.
- **In-repo precedent:** the sibling list components already fix this exact shape — `Card`
  (`src/components/Card/index.tsx:1435,1450` render `<ul role="list">`, documented in
  `CardFamily.stories.tsx:31` as "the list-semantics a11y pattern") and `ListItemCard`
  (`src/components/ListItemCard/index.tsx:16`). `List` was the outlier.
- **Fix:** added `role="list"` to the root `<ul>` (`index.tsx:88`). The canonical fix (per Scott
  O'Hara, "Fixing lists") only needs the role on the container — the native `<li>` children
  regain their `listitem` semantics once the parent is a list again, so `ListItem` was left
  unchanged. Purely additive; no existing `data-*`/`role`/`aria` attribute was removed or renamed,
  and the `data-component="List"` test selector is preserved.
- **Cross-component class:** `list-semantics-removed-by-list-style-none`.

## Reading & screen reader

- **List semantics:** fixed above — the list is now programmatically exposed as a list (1.3.1).
- **Accessible names / interactive elements:** the component renders **no interactive elements**
  itself (no `<button>`/`<a>`/handlers), so there is no control missing an accessible name within
  my scope. Row interactivity is a consumer concern.
- **Focus / `:focus-visible`:** N/A — no focusable element is produced by List. No overlay/dialog,
  so no focus trap / Escape / restore concerns.
- **Forms:** N/A — List is not a form control.
- **Dynamic updates / live regions:** N/A — List renders static content passed as children; it
  performs no async loading or state change that would need `role="status"`/`aria-live`.
- **Color-alone state (1.4.1):** N/A — List exposes no state (selected/error/disabled). Theming
  (`data-theme`) only changes palette; it conveys no information by color alone.
- **Motion (2.3.3):** N/A — `List.module.css` contains **no `transition` or `animation`**, so no
  `prefers-reduced-motion` handling is required.

## Deferred

None inside List's own contract. One adjacent observation (NOT owned — do not fix here):

- **Icon svgs lack a default text alternative** — `src/components/Icons/Home.tsx:45` (and every
  sibling icon) renders `<svg fill="currentColor">` with **no `aria-hidden`, no `role="img"`, and
  no `<title>`**. A leading icon inside `ListItemIcon` is decorative (the `ListItemText` label
  carries the meaning), so ideally these svgs would default to `aria-hidden="true"` (or accept a
  `title`/`aria-label` when meaningful). This is an **Icons-component** decision, not List's:
  `ListItemIcon` must NOT blanket-force `aria-hidden` on its wrapper because a consumer may place a
  *meaningful* icon there, and the wrapper can't know. In practice most AT ignore a nameless,
  roleless `<svg>`, so the current impact is low.
  - **File:** `src/components/Icons/*.tsx` (e.g. `Home.tsx:45`), shared via `Icons/icon.module.css`.
  - **Suggested change:** in the shared icon render, default `aria-hidden="true"` on the `<svg>`
    unless the caller passes an `aria-label`/`title` (then emit `role="img"` + `<title>`).
  - **Class:** `icon-missing-aria-hidden`.
